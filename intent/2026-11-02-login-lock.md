# 로그인 잠금: 맞는 코드는 막지 않기

- 날짜: 2026-11-02
- 상태: 만드는 중
- 관련 단계: 92단계 v0.97 (서버 v0.57)

## 한 줄 요약

누군가 틀린 접속 코드를 많이 보내도, 맞는 코드를 가진 학생·선생님은 막히지 않게 한다.

## 왜 만드나

- 중간 점검(2026-11-02)에서 발견: 서버가 틀린 코드 횟수를 모든 사람에 대해 하나로 센다.
  10분 안에 20번 틀리면 맞는 코드를 가진 사람까지 모든 요청이 10분 동안 막힌다.
- 웹앱 주소는 공개 저장소에 있으므로, 코드가 없는 사람도 20번만 보내면 수업 중에 반 전체를 멈출 수 있다.
- 다른 AI(Gemini)의 교차 확인에서도 같은 결론이었다.

## 누가 쓰나

- 학생, 선생님, 테스터 모두 같은 방식. 로그인뿐 아니라 접속 코드를 확인하는 모든 요청(대화 시작, 피드백 등).

## 범위

**만드는 것**
- 맞는 코드(active 학생)를 먼저 확인해서, 맞으면 잠금과 상관없이 통과
- 틀린 코드일 때만 실패 횟수를 확인하고 늘린다 (지금처럼 10분에 20번, 잠긴 동안의 시도는 세지 않음)
- 잠금이 처음 걸릴 때 실행 기록에 한 줄 (접속 코드는 남기지 않음)
- 가짜 시트 시험: 성공, 실패, 잠금, 잠금 풀림

**이번에는 안 만드는 것**
- 앱 화면 문구 변경 (잠긴 동안 틀린 코드에는 지금처럼 '10분 뒤에 다시')
- 코드마다 따로 세기, 주소(IP)별 막기 (Apps Script에서는 요청한 사람의 주소를 알 수 없다)
- 마구 호출 자체를 막기 (틀린 시도도 시트를 읽고 Apps Script 사용량을 쓴다)

## 지켜야 할 조건

- 접속 코드는 로그에 남기지 않는다.
- Code.gs 한 파일, 시트 칸 변경 없음, setup 필요 없음.
- 코드 맞히기 방어는 코드의 길이와 무작위성에 맡긴다 → 선생님·테스터 코드는 무작위 10자 이상으로.

## 결정

| 정한 것 | 이유 | 버리거나 미룬 다른 안 |
| --- | --- | --- |
| 맞는 코드를 먼저 확인 | 잠금이 학생을 막지 않게 | 지금처럼 잠금을 먼저 확인 (반 전체가 멈춤) |
| 틀린 코드 횟수는 남긴다 | 지금 동작과 가장 가깝고, 실행 기록으로 공격을 알아챌 수 있다 | 아예 없애기 |
| 맞는 코드로 들어와도 횟수를 되돌리지 않는다 | 코드를 가진 사람이 다른 사람을 위해 브레이크를 풀 수 없게 | 성공하면 0으로 |
| 화면 문구는 그대로 | 앱을 바꾸지 않아도 되고, 잠금은 드물다 | '코드를 다시 확인해 주세요'로 바꾸기 |
| 코드 길이(8자 이상)로 맞히기를 막는다 | 맞는 코드가 먼저 통과하면 잠금은 맞히기를 막지 못한다 | — |

## 성공 기준

- [ ] 실패 횟수가 20 이상이어도 맞는 코드로 로그인·챕터 목록이 통과한다 (시험)
- [ ] 틀린 코드는 INVALID_CODE, 횟수 +1 (시험)
- [ ] 20번 틀린 뒤 틀린 코드는 TOO_MANY_TRIES, 횟수는 더 늘지 않는다 (시험)
- [ ] active가 아닌 학생의 코드는 틀린 코드처럼, 빈 코드는 세지 않는다 (시험)
- [ ] 10분이 지나면 다시 INVALID_CODE (시험에서는 캐시 값을 지워 흉내)
- [ ] 실행 기록에 접속 코드가 남지 않는다 (시험)
- [ ] 배포 뒤 휴대폰에서 로그인이 된다 (수업에서 확인)

## 열린 질문 · 다음에 할 것

- 선생님·테스터 코드를 무작위 10자 이상으로 바꾸기 (시트, 선생님이 직접)
- 학생 코드는 학생이 고른 아이디라 아는 사람이 맞힐 수 있다. 피해는 그 학생의 하루 한도 안이라 이번에는 그대로 둔다.

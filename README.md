# Tutoreal

간호사를 위한 영어 디지털 교과서 웹앱. 지금은 내시경실 상황 챕터로 시작했고, 나중에 일반 회화로 넓힐 수 있다.
챕터를 고르면 무작위 시나리오의 AI 수검자(Gemini Live)와 음성으로 대화하고,
대화가 끝나면 피드백과 대화 노트를 받는다.

- 웹 주소: https://vayaconkev.github.io/tutoreal/
- 관리자: Kevin (코딩 경험 없음 → 코드는 Claude가 작성, Kevin은 붙여넣기·클릭·테스트)
- 개인 프로젝트, 사업화 목적 없음

## 구조

| 구성 | 위치 |
| --- | --- |
| 웹앱 화면 | 이 저장소 → GitHub Pages |
| 서버 | Google Apps Script (`server/Code.gs`가 원본) |
| 데이터베이스 + 교과서 내용 | 구글 시트 |
| 음성 AI | Gemini Live API (임시 토큰으로 브라우저에서 직접 연결) |
| 텍스트 AI | Gemini 텍스트 API (자막 번역, 피드백) |

## 규칙 (코드가 꼬이지 않게)

1. 코드의 원본은 이 폴더 하나. GitHub 웹사이트나 Apps Script 편집기에서 직접 고치지 않는다.
2. 챕터·시나리오·지시문·핵심 단어는 구글 시트에만 둔다. 코드에 넣지 않는다.
3. 한 단계에 한 기능만. '끝났다는 기준'을 확인한 뒤 다음으로.
4. 단계마다 GitHub Desktop으로 커밋한다.
5. 화면에 버전 번호를 표시하고, 바꿀 때마다 CHANGELOG.md에 한 줄 적는다.
6. 시트 칸 이름은 바꾸지 않는다. 추가는 가능, 변경·삭제는 코드와 함께.
7. 바뀌는 값은 한 곳에: 서버 주소·버전은 `js/config.js`, 모델 이름·한도·예산은 시트 설정 탭.
8. 새 기능은 Kevin의 접속 코드로 먼저 테스트한 뒤 학생에게 알린다.
9. 비밀은 코드에 넣지 않는다. 이 저장소는 공개다. API 키는 Apps Script 스크립트 속성에만, 접속 코드는 시트에만.

## 선생님 기능

- `students` 탭의 `role` 칸에 `teacher`라고 적힌 접속 코드로 들어오면 앱에 '선생님 요약'이 보인다 (학생은 빈칸). 서버도 요청마다 역할을 확인한다.
- 요약은 시트 메뉴 'Tutoreal → 요약 새로고침'(summary 탭)과 앱의 '선생님 요약'이 같은 계산을 쓴다. 기간은 settings의 `last_class_date`부터, 비어 있으면 최근 7일.
- 요약은 과정별: 앱에서는 위의 '영어 과정 / 중국어 과정'으로 고르고, summary 탭에는 과정마다 이어서 적는다. 중국어 과정 기간은 `last_class_date_zh` (비우면 `last_class_date`).
- 선생님 접속 코드는 학생과 공유하지 않는다.

## 과정 (영어·중국어)

- `students` 탭과 `chapters` 탭의 `course` 칸으로 과정을 나눈다: `en` 영어, `zh` 중국어. 빈칸은 영어.
- 학생은 자기 과정의 챕터만 받는다. 선생님 코드는 모든 과정의 챕터를 받는다 (과정별 제목). 챕터 목록은 접속 코드로 요청할 때만 주고, 대화 시작·발음 코칭도 서버가 과정을 확인한다.
- 지시문·받아쓰기 언어·병음 같은 과정별 기능은 연 챕터의 과정을 따른다.
- 학생끼리는 과정과 관계없이 서로의 기록을 볼 수 없다 (내 기록은 각자 휴대폰에, 공유한 대화는 선생님만).
- 중국어 과정은 선생님 코드로 바로 테스트할 수 있다 (학생 화면 그대로 보려면 course가 zh인 테스트용 코드).
- 지시문(prompts 탭)도 과정별: 영어는 `patient-…`, `feedback-…`, `pron-…`, `insight-…`, 중국어는 앞에 `zh-`를 붙이고 대화 상대는 `zh-partner-…`. 그 과정의 지시문이 없으면 그 기능은 '준비 중'으로 나온다.
- 중국어 시나리오의 칸: `name` 상대 이름, `sex` 목소리, `country` China/Taiwan (받아쓰기 언어와 말투), `exam` 상대의 역할·장소 (대화 화면 카드에 보임), `dob` 비움.
- 학생 이름·브랜드 이름은 코드에 넣지 않고 시트(students의 profile, chapters의 keywords, scenarios의 twist 칸)에만 적는다.
- `students` 탭의 `profile`(학생 소개): 이름·회사·하는 일 같은 사실. AI 상대의 힌트와 피드백 예문이 이 사실로 문장을 만든다 (Gemini로 함께 보내진다). 비워 두면 쓰지 않는다.
- 중국어 문장 연습(drills 탭): `sentence`의 [대괄호]가 빈칸, `pron`은 문장 전체의 교과서식 병음 (성조 코칭의 기준이자 정답 화면의 병음). 영어는 `pron`에 어려운 단어의 발음 안내만.

## 데이터 원칙

- 음성은 저장하지 않는다.
- 대화가 끝날 때마다 학습자가 공유 여부를 선택한다. 공유하면 시트에, 안 하면 학생 기기(브라우저)에만 저장.
- 공유와 관계없이 항상 남는 것은 사용 시간뿐이다.
- 실제 환자 정보는 쓰지 않는다.
- 문장 연습의 발음 코칭은 학생이 말한 몇 초의 소리를 서버를 거쳐 Gemini 텍스트 모델로 한 번 보낸다. 소리와 들린 글자는 저장하지 않고, pron_checks 탭에 결과(great/good/retry)와 비용만 남긴다.
- 중국어 과정의 자막 도우미(병음·한국어 뜻)는 대화 중 상대(AI)가 한 말 한 줄씩을 서버를 거쳐 Gemini 텍스트 모델로 보낸다. 저장하지 않는다.
- 피드백을 만들기 위해 대화 글자(음성 아님)를 서버를 거쳐 Gemini 텍스트 모델로 한 번 보낸다. 공유를 고르지 않으면 시트에 저장하지 않는다. 대화를 저장해 두는 Interactions API가 아니라 generateContent를 쓴다.
- **Gemini API는 유료 등급(Tier 1, 선불 크레딧)을 쓴다 (2026-10-12 전환).** 유료 등급은 보낸 음성·글자를 구글 제품 개선에 쓰지 않는다 (악용 감시용으로 짧게만 기록). 무료 등급은 제품 개선에 쓰이고 사람이 검토할 수 있어 학생용으로 쓰지 않는다.
- 비용 안전장치 두 겹: ① 선불 크레딧 — 충전한 만큼만 쓰이고, 다 쓰면 모든 요청이 멈춘다 (자동 충전은 켜지 않는다). ② settings 탭의 월 예산(monthly_budget_usd) — 앱이 예상 비용으로 대화를 막는다.
- 크레딧이 다 떨어지면 대화가 '연결이 끊겼어요 (1011: ... prepayment credits are depleted ...)'로 끝난다 → AI Studio의 Billing에서 충전한다 (반영까지 최대 10분).
